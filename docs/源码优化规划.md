# JipperKeyViewer 源码优化规划

> 状态：已保存，待执行。
> 目标：结构清晰、语法统一、热路径低分配、可公开克隆/构建/贡献；性能以不回归为底线。

## 1. 总体原则

1. 先开源基线（许可证/仓库/CI），再重构代码。
2. 结构、语法、性能分阶段提交，每阶段可回退、可验证。
3. 一次只做一类变更，避免“重构+优化+改行为”混在一起。
4. 参考原 Mod 的 Core/Settings/Rendering/Rain/GUI/Util 分层与 GUI 分页，但不照搬 Unity/TMP/IMGUI 实现。
5. 性能目标以当前实测为基线：CPU/GPU <8%、60fps、覆盖层穿透、OBS 正常、无输入延迟。

## 2. 模块分类（6 类）

| 类别 | 主要文件 | 职责 |
|---|---|---|
| A 应用外壳与生命周期 | `Program.cs` | 入口、单实例、Win32 窗口/WndProc、主循环、托盘、热键、设置线程、覆盖层切换、窗口记忆、.jkv 关联/导入、渲染器创建 |
| B 配置、方案与持久化 | `Config/*` | 配置模型、默认值、加载/保存、布局注册表、方案管理、原 Mod 配置导入、.jkv 导入 |
| C 输入、计数与键雨状态 | `Core/*` | 全局键盘钩子、按键状态/计数、Unity KeyCode、键雨状态机、缓动 |
| D 图形后端与基础设施 | `Graphics/*` | CPU 光栅化、D3D11/D2D1/DComp、交换链/ULW、文字 sprite、字体、纹理/画刷缓存 |
| E 键位布局与画面呈现 | `Render/KeyRenderer.cs` | 4K–108K 布局表、槽位几何、键帽/描边/渐变、光晕、KPS/Total、键雨绘制、按压动画 |
| F 设置界面、主题与本地化 | `UI/*` | 设置窗口、颜色选择器、确认弹窗、页签、主题、中英韩本地化 |

辅助：`Diagnostics/MemoryStats.cs` 为临时诊断，不单独成类。

## 3. 当前主要结构问题

- `Program.cs` 约 1.3k 行，静态 God Object，承担过多职责。
- `TransparentRenderer` 约 1.6k 行，CPU 光栅化 + D3D 交换链 + ULW + DComp + 文字/字体/缓存/日志混在一起。
- `SettingsWindowWpf.xaml.cs` 约 2.1k 行，视图、配置、颜色、方案、导入、语言、主题、改键全在一起。
- `KeyRenderer` 约 1.4k 行，布局数据 + 运行时状态 + 绘制混合。
- `AppConfig` 655 行，模型 + 持久化 + 默认值 + 颜色转换混合。
- 反向依赖：`Core.Rain → Graphics.Color4/GraphicsLog`；`Config.ProfileImport → Core.KeyCode`。
- 死代码/临时代码：旧 `UI/SettingsWindow.cs`（无调用方）、`PreferComposition`/`SwitchComposition`、`Diagnostics/MemoryStats.cs`、过时注释。

## 5. 分阶段计划

### P0 开源基线（先做）

- 建立 git 仓库与目录结构；`.gitignore` 排除 `bin/obj/dist/checkpoints/logs/.vs`。
- 选择 LICENSE（建议 MIT，与原 Mod 一致，但需确认代码与资源授权）。
- `THIRD_PARTY_NOTICES.md`；**资源许可证审计**：
  - `MAPLESTORY_OTF_BOLD.OTF` 是否允许再分发；
  - `hurme-geometric-bold.ttf`、`shiliuzi-laihu2.ttf`、Noto Sans SC；
  - 图片、图标、banner。
  - 不能确认的资源改为用户自备或替换为 OFL 字体。
- 双语 README、构建说明、功能说明、截图。
- `.editorconfig`、`.gitattributes`、`global.json`、`Directory.Build.props`。
- GitHub Actions：Windows `dotnet build` / `test` / `publish`；Issue/PR 模板、CHANGELOG。

验收：全新 clone 一条命令构建成功；CI 绿；仓库无二进制/本地路径/日志。

### P1 机械清理与语法统一

- 删除旧 `UI/SettingsWindow.cs`、`PreferComposition`/composition 死路径、临时 `[MEM]` 日志。
- `GraphicsLog` 移到 `Infrastructure/Logging`。
- 修正过时注释；统一 file-scoped namespace、`using`、命名、`var` 使用。
- 清理编译警告，之后启用 `TreatWarningsAsErrors`；引入 `dotnet format`/内置 Analyzer。
- 不改变行为。

验收：0 warning、0 error；视觉与功能一致。

### P2 拆应用外壳

拆 `Program.cs`：

- `AppBootstrap`：入口、单实例、启动顺序；
- `MainWindowHost`：Win32 窗口/WndProc/WM_SIZE/置顶；
- `TrayService`、`HotkeyService`；
- `SettingsHost`：独立 STA 线程与 Dispatcher；
- `OverlayController`：普通/覆盖层切换、窗口重建、位置记忆；
- `PackageService`：.jkv 关联、拖放、导入；
- `RenderLoop`：主循环、帧率日志。

验收：`Program.cs` < 300 行；覆盖层/OBS/热键/托盘回归。

### P3 拆设置界面

按原 Mod GUI 分页思路拆 `SettingsWindowWpf`：

- 壳 + `Pages/DisplayPage`、`LayoutPage`、`AppearancePage`、`KeysPage`、`RainPage`、`ProfilesPage`、`AboutPage`；
- 每页 `UserControl` + `ViewModel`；
- `ColorPickerWindow`、`ConfirmDialog` 独立；
- `ThemeService`、`LocalizationService`；
- `INotifyPropertyChanged` + 命令，减少 code-behind。

验收：设置功能全部不变；code-behind 大幅缩减；内存不回归。

### P4 拆渲染后端与绘制

- `IRenderBackend`：`Init/Resize/BeginFrame` + 图元 + `Present/Dispose`；
- `CpuLayeredBackend`、`D3DHwndBackend`、`DCompOverlayBackend`；
- 抽出 `TextSpriteCache`（LRU）、`FontService`、`KvLayout`/`LayoutCatalog`、`KvPainter`；
- 性能项：GPU 路径去掉 CPU `_pixels/_presentPixels`；热路径零 `new`/LINQ/字符串拼接；缓存预算；资源生命周期。
- 保持覆盖层穿透、OBS 捕获、60fps。

验收：视觉一致；CPU/GPU 不高于当前；内存不回归。

### P5 拆配置与核心模型

- `Config/Models` 纯 POCO；`Stores` 加载/保存/迁移；`Import` 原 Mod/.jkv；`Profiles` 方案。
- 把 `KeyCode`、颜色、日志移出 `Core → Graphics` 反向依赖。
- 补纯逻辑单元测试。

验收：旧配置/方案/分享包兼容；导入失败回滚。

### P6 文档与发布收尾

- `docs/architecture.md`、`building.md`、`assets-license.md`；
- README、CONTRIBUTING、CHANGELOG、GitHub Release workflow；
- 可选代码签名；
- 干净 clone + build + run 验收。

## 6. 语法与代码风格

- C# 12 / .NET 8，file-scoped namespace；
- Nullable 开启；公开 API 加 XML 注释；
- 私有字段 `_camelCase`，方法 `PascalCase`；
- 禁止空 `catch`；异常记录上下文；
- P/Invoke 统一放 `Interop/`，命名 `XxxNative`；
- COM/原生资源统一 `Dispose`/`using`；
- 热路径禁止 LINQ、字符串拼接、每帧 `new`；
- 中文注释可保留，公开文档双语；
- 提交前缀 `feat/fix/refactor/perf/docs/chore`。

## 7. 测试与性能验收

自动化优先覆盖纯逻辑：

- `KvEasing`；
- `Rain` 运动/淡出/回收；
- `AppConfig` 默认值/数组修复/迁移；
- `ProfileImport`/`PackageImporter`（zip 安全、失败回滚）；
- `LayoutRegistry`/布局几何；
- `UiTextTable` 词条完整性。

手动回归：16K/75K/108K、普通/覆盖层、透明/穿透/置顶/不抢焦点/任务栏、OBS、高频输入、改键、颜色、方案、导入导出、高刷。

性能预算：

| 指标 | 目标 |
|---|---|
| CPU | <8% |
| GPU | <8% |
| 帧率 | 60fps（覆盖层 Present(1)） |
| 设置关闭私有工作集 | ≤110–120MB |
| 设置打开过 | ≤150MB |
| 托管堆 | ≤20MB，长期不增长 |
| 热路径每帧分配 | 接近 0 |
| 输入延迟 | 不高于当前 |

## 8. 风险

| 风险 | 应对 |
|---|---|
| 字体/图片许可证不明（阻塞开源） | P0 先审计；不能确认就替换/用户自备 |
| 渲染重构破坏 OBS/穿透 | P4 单独阶段，逐项回归 |
| 设置 UI 重构工作量大 | 先 partial 分页，再 MVVM |
| 过度拆分多程序集 | 先单应用 + 测试项目 |
| 性能微优化引入 bug | 以不回归为底线，不做无数据支撑的优化 |

## 9. 建议执行顺序

P0 → P1 → P2 → P3 → P4 → P5/P6。

当前优先：P0 仓库结构与许可证审计；不先动源码逻辑。


## 10. 补丁分级与合并（允许“主体 + 补丁”）

详细清单见 `docs/patch-debt.md`。总原则：

- **合并**：产品行为、可建模/参数化、可测试的补丁 → 主实现；
- **保留独立**：Win32/DWM/D3D/DComp/OBS、第三方格式兼容、经验性视觉常量 → 适配层；
- **删除**：死代码、重复补丁、不可达分支。

新增阶段 **P1.3（P2 之前）**：补丁清单与标记，不改变行为。

| 阶段 | 补丁合并重点 | 保留独立 |
|---|---|---|
| P1.3 | 建立 `docs/patch-debt.md`、标注 Merge/Keep/Delete、准备回归 | — |
| P2 | 窗口状态、RendererFactory、OverlayController、PackageService、KeyCodeMapper | Win32 单实例/热键/IME/窗口样式 |
| P3 | 本地化前缀兜底、设置窗重复事件补丁 | UI 像素级样式常量 |
| P4 | 字体 baseline、计数格式、布局/绘制分层 | DComp 覆盖层、OBS 交换链契约、GDI+ 文字栅格化、离屏 copy workaround |
| P5 | 配置规范化、旧键迁移、每键颜色回退 | 原 Mod ProfileData / 旧 `.jkv` 导入适配器 |
| P6 | 最终审计：业务代码无平台特判 | `Rendering/Backends`、`Config/Import`、`Interop/Platform` |

合并前必须有回归项；合并后删除旧补丁分支，禁止保留两份行为。
